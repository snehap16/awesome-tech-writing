# Sample Portfolio

## What is this?

This is a complete, production-grade technical writing sample portfolio built around a fictional SaaS product called **WorkIt**. It contains real documentation deliverables that you can study, reference, and use as a benchmark when building your own portfolio.

---

## Why I created this

Breaking into technical writing is hard when every job post asks for a portfolio, but building a portfolio requires practical examples. This sample portfolio solves that problem.

It shows you what complete, job-ready documentation looks like for a real-world software product so you know exactly what hiring managers expect.

---

## Getting started with WorkIt

All documents in this portfolio are written for a fictional product called **WorkIt**.

### About WorkIt

WorkIt is a cloud-based case management platform that helps support and operations teams create, assign, track, and resolve cases from a single interface.

WorkIt has three core resources:

- **Cases** — individual issues or requests that need to be resolved.
- **Projects** — groups of related cases organized by team or goal.
- **Users** — team members who are assigned to and resolve cases.

*Note: WorkIt is not a real product. It exists solely as a practice subject for this portfolio sample set.*

## 💡 How to Use This Sample to Build Your Own Portfolio

If you are building your own technical writing portfolio, follow these 3 steps:

1. **Pick an Open Source Tool or Fictional Product:** Choose a tool you like (e.g., Docker, Strapi, or create a mock product like WorkIt).
2. **Use These Documents as Your Structural Template:** Follow the heading hierarchy, prerequisite callouts, code block formats, and error troubleshooting tables demonstrated in `installation-guide.md` and `developers-guide.md`.
3. **Publish on GitHub or a Static Site:** Host your portfolio on GitHub Pages or Notion to show prospective employers your Docs-as-Code skills!
