# Portfolio

---

## What is this section?

This is where you build proof that you can write.

A portfolio is the single most important thing you need as a tech writer, especially if you are switching careers or just starting. Recruiters and hiring managers will ask for it. This section gives you everything you need to build one from scratch, even if you have zero work experience.

## Start here

If you are new to this, do not overthink it. Follow this order:

1. Read the [portfolio guide](./guide/) to understand what you need and why.
2. Go to [fictional-product](./fictional-product/) to learn about the practice API.
3. Pick a [writing prompt](./prompts/) and write your first sample.
4. Compare your work with the [completed samples](./samples/).

That is it. You do not need a job to get started.

---

## What makes a good portfolio?

Here is what actually matters:

- **3 to 5 strong samples** are better than 10 average ones. Quality over quantity, always.
- **Variety counts.** Include different doc types: a how-to guide, an API reference, a README, and release notes. Show that you can switch gears.
- **Context matters.** For each sample, write a short note explaining what it is, who the audience is, and what decisions you made. This shows how you think.
- **Keep it current.** An outdated portfolio is worse than a short one. Remove samples you are not proud of.

---

## What to avoid

- Do not include work covered by an NDA without permission.
- Do not include unfinished drafts unless you clearly label them as works in progress.
- Do not use lorem ipsum or placeholder content. Every sample should look intentional.

---

## Where to host it

You have a few good options:

- **GitHub Pages** (free, version-controlled, great for developer-facing roles)
- **Notion** (easy to set up, looks clean, good for non-technical audiences)
- **Read the Docs** (ideal if you want to show you can work with documentation tools)
- **Your own site** (most effort, most control)

There is no wrong answer here. Pick what you can maintain consistently.

## A note on the fictional product

All the prompts and samples in this section are based on a demo REST API called **WorkIt**. WorkIt is a task management API. It is fictional, but the documentation you write for it is real and can be added to your portfolio.

Using a shared fictional product keeps everyone on the same page and makes it easier to compare approaches.
