01 Background & Philosophy

What is this Prompt Library?

Most AI prompts produce generic, superficial text because they lack structural guardrails, context containers, and negative style constraints. This library was engineered to fix that.

🎯 The Problem with Traditional Prompting

When you type "Write an API reference for our user endpoints" into an AI model, the model generates hallucinated schemas, conversational filler ("Sure, I'd be happy to help!"), and unstructured paragraphs. Professional technical communication demands deterministic structure, syntactic precision, and authoritative tone.

📐 Frontier Prompt Architecture

Every prompt in this repository adheres to a strict multi-layer architectural pattern optimized for frontier LLMs (such as Claude 3.5 Sonnet, GPT-4o, and Gemini 1.5 Pro):

1. Role & Persona Framing Establishes senior-level perspective (e.g., "You are a Staff Technical Writer and Developer Advocate...") to eliminate apologetic tone and superficial fluff.
2. Structured <input_sources> Dedicated XML context containers advising you on what files to attach (.json, .yaml, .md) or raw code diffs to paste, grounding the model in reality.
3. Algorithmic <instructions> Numbered sequential execution steps, style rules (Microsoft Writing Style Guide compliance, sentence case, zero em-dashes), and negative constraints.
4. Strict <output_format> Commands the model to deliver pure, copy-pasteable Markdown tables, syntax-highlighted code fences, or diff blocks without conversational preambles.
💡
Why XML tags? Frontier AI models like Anthropic Claude and OpenAI GPT-4o are heavily fine-tuned to parse semantic XML markers like <input_sources> and <instructions>. This prevents instruction injection and ensures the AI never confuses your reference data with its assigned task.
02 Architecture & Taxonomy

Writing in technology is not one-dimensional. A technical communicator writes API specs in the morning, drafts an executive project update at noon, and writes a thought leadership blog post or release note in the afternoon. The library is partitioned into two core domains and nine specialized subcategories.

⚙️

Domain: Technical Writing (51 Prompts)

CORE ENGINEERING

Dedicated to software documentation engineers, developer relations (DevRel), and systems architects who treat documentation with the same rigor as production code.

Generates API reference pages, CLI command manuals, Architecture Decision Records (ADRs), error troubleshooting catalogs, SDK quickstarts, and release notes.

Why: Eliminates the tedious boilerplate of document drafting while enforcing strict technical accuracy.

Strategy & Planning

Provides documentation plans, content gap matrices, information architecture models, audience persona profiles, and localization readiness checklists.

Why: Guides high-level content strategy before a single sentence of documentation is drafted.

Video & Audio

Drafts screencast walkthrough scripts, YouTube tutorial storyboards, and developer interview podcast outlines with visual and audio staging cues.

Why: Developers increasingly consume technical learning visually through screencasts and video guides.

Format & Style

Audits prose against the Microsoft Writing Style Guide, converts unstructured text into clean Markdown, standardizes terminologies, and lints for tone.

Why: Ensures consistent voice across a global engineering organization with hundreds of contributors.

03 Execution Framework

How to Use the Prompts: The 3-Step Workflow

Follow this frictionless workflow to go from a documentation requirement to a finished draft in under three minutes.

1

Find & Filter Your Prompt

Locate the exact prompt engineered for your specific deliverable

Use the top-tier Domain Tabs to narrow down between Technical Writing, General Writing, or your Saved prompts. Then, click any Subcategory Pill to hone in on your task. You can also type keywords like "REST API", "Decline Email", or "Troubleshooting" directly into the global search bar for instant full-text matching across titles, use cases, and tags.

2

Customize Variables & Attach Sources

Populate bracketed parameters and feed actual context into the model

Click Customize on any prompt card to trigger the built-in variable editor modal. Instead of manually editing messy text, type your values directly into the auto-generated input fields. The live preview updates in real time.

Crucially, review the <input_sources> section. If the prompt suggests attaching a Swagger spec, a Git commit diff, or a support ticket, have that file ready to upload into your AI tool.

3

Launch in AI & Refine the Output

Send directly to your preferred AI model with a single click

Click Launch in AI ▾ and select your model of choice: ChatGPT, Claude, Google Gemini, Perplexity, or Microsoft Copilot. The app automatically copies your customized prompt to the clipboard and opens the AI model's chat interface. Simply paste (Cmd+V or Ctrl+V), attach any source files, and press send.

04 Interactive Customizer

Customizing Variables in Depth

Learn how placeholder tokens are constructed and how to provide optimal context to get publication-grade output.

🔍 Anatomy of a Variable Placeholder

Every prompt contains bracketed tokens styled with helpful guidance, formatted as:

[VARIABLE_NAME, e.g., Concrete Example or Recommended Option]

The comma provides immediate inspiration so you understand what level of detail the AI expects without needing to guess.

Interactive Variable Simulation Live Form Preview
Generated Prompt Excerpt:
You are a Senior API Technical Writer. Create an endpoint reference for Stripe Webhook Delivery API using HMAC-SHA256 Signature Header authentication. <input_sources> Attached documents (recommended): - Attach the OpenAPI / Swagger JSON or YAML specification. </input_sources>
💡
Rule of Thumb: Never leave brackets unfilled in your final prompt! If a variable doesn't apply to your specific project (for example, if an API has no request body), simply delete that line from the <input_sources> block before submitting.
05 Model Capabilities

Launching in AI Models: Which Model to Pick?

The library integrates with all major frontier models. Each model possesses unique strengths for technical and creative writing.

Anthropic Claude Top Choice

Unmatched adherence to structural XML tags, negative constraints (e.g. "do not use em-dashes"), and nuanced, human-sounding prose without corporate clichés.

Best For: API docs, architectural decision records, style guide adherence, essays.
Google Gemini Massive Context

Its huge 1M-2M token context window allows you to upload entire code repositories, 50-page PDF specifications, or complete video recordings in one prompt.

Best For: Large documentation audits, full-repo analysis, video-to-tutorial transcription.
ChatGPT (GPT-4o) Fast & Conversational

Exceptionally fast code generation, interactive multi-turn brainstorming, and intuitive file-browsing with Advanced Data Analysis.

Best For: Rapid first drafts, conversational editing, social threads, troubleshooting.
Perplexity AI Live Web Grounding

Performs real-time search engine queries across official documentation, GitHub repositories, and package registries to ensure syntax matches current release versions.

Best For: Verification of latest library versions, external API citations, competitive tech audits.
06 Mastery

Pro Tips for Seasoned Writers

Techniques to elevate your AI-generated technical drafts from acceptable to publication-grade.

  • Iterate with editorial follow-ups: Never accept the first output as final. Follow up immediately with: "Review this draft against the Microsoft Writing Style Guide: change all passive constructions to active voice, verify second-person ('you'), and ensure headings are in sentence case."
  • The Zero Em-Dash Standard: In technical documentation, em-dashes (—) often indicate fractured clauses and informal rambling. Our prompts enforce clean, declarative sentence boundaries using colons, parentheses, or separate sentences.
  • Export collections for team wikis: Use the Export ▾ button on the main page to download your filtered prompts as clean Markdown (.md) or JSON (.json). Import them directly into Notion, Confluence, or company handbook repositories.
  • Bookmark your daily drivers: Click the bookmark star on any prompt card to save it into the Saved domain tab. Bookmarks are stored persistently in your local browser storage.
